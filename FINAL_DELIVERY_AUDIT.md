## 3. L2 integrity summary (`evidence/l2_integrity_report.json`)

| Dataset | Records | Snapshots (line) | Deltas | `u` ≠ prev + 1 | `seq` not increasing between deltas | ts / cts regressions | Malformed / duplicate records | Crossed or locked | Max depth (advertised) | End-of-file snapshot reproduced |
|---|---:|---|---:|---:|---:|---|---|---:|---|---|
| ORDIUSDT 2026-10-01 | 339,156 | 2 (first, last) | 339,154 | 0 | 0 | 0 / 0 | 0 / 0 | 0 | 200 (200) | yes |
| 10000LADYSUSDT 2025-10-01 | 553,443 | 2 (first, last) | 553,441 | 0 | 0 | 0 / 0 | 0 / 0 | 0 | 200 (200) | yes |
| 10000LADYSUSDT 2025-06-01 | 372,859 | 2 (first, last) | 372,857 | 0 | 0 | 0 / 0 | 0 / 0 | 0 | 500 (500) | yes |

**What "zero gaps" means.** It means `update_id_not_plus_one = 0`: every delta's `u`
equals the previous record's `u` + 1.
* **Bybit documents:** `u` is an "update ID", and `u = 1` signals a restart. It does not
  document +1 increments.
* **Observed in these three files:** +1 on every delta, `seq` strictly increasing between
  deltas, and an end-of-file snapshot that repeats the last delta's `u`.
* **Our rule:** any other increment is a SEQUENCE_GAP and invalidates the book.

So the statement is an observation about three files, not a guarantee about the archive
or the live stream.

**Quiet intervals** (longest period without any book message):

| Dataset | Longest quiet interval | Intervals over 5 s | Intervals over 30 s |
|---|---:|---:|---:|
| ORDIUSDT 2026-10-01 | 10.3 s | 168 | 0 |
| 10000LADYSUSDT 2025-10-01 | 6.8 s | 2 | 0 |
| 10000LADYSUSDT 2025-06-01 | 8.7 s | 59 | 0 |

These intervals cannot prove or disprove missing data, because the archive has no
heartbeat.

**Found during this pass.** The independent script first flagged one non-increasing `seq`
per 10000LADYSUSDT file. Both cases were the end-of-file snapshot repeating the last
delta's `u` and `seq`. The check now covers delta-to-delta order only, and each snapshot's
`u`/`seq` relation to the previous record is reported explicitly.

## 7. Limitations and claims that must be disclosed

* This is technical feasibility only. There is no profitability claim, and no returns or
  costs were computed. A successful replay is not a predictive strategy.
* Only one symbol-day went through the detector. The thresholds are research hypotheses,
  untuned. The pre-run threshold claim is the author's statement and has no version
  history behind it.
* `u` + 1 continuity and the meaning of the end-of-file snapshot are observed, not
  documented. The archive `side` column behaves as the taker side (observed, not
  documented).
* Quiet intervals cannot prove completeness. Coverage of other symbols or dates, newly
  listed contracts and the live WebSocket is not verified.
* Execution/cancellation attribution is approximate (100 ms ob200 batching). The replay is
  zero-latency on `cts`. OI, funding and liquidations are not integrated.
* Determinism was verified across processes and a clean reinstall on one Windows machine.
  Other operating systems were not tested.
* Redistribution of the derived logs (which contain prices) under Bybit/Tardis.dev terms
  is not verified.
* None of the full-project acceptance items has been run or passed: out-of-sample tests,
  ≥ 100 trades per direction, PF and expectancy, costs, drawdown, robustness tests, Demo
  Trading, and independent review.
